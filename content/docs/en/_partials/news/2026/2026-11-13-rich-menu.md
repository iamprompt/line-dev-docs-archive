We've added a new page, [Stop displaying rich menus](/docs/messaging-api/stop-displaying-rich-menu/), to the Messaging API documentation. This page explains how to stop displaying a rich menu and what to keep in mind when doing so.

### Background

There are times when you may want to stop displaying the current rich menu, such as when an ongoing campaign ends or a seasonal product is no longer available. Depending on the type of rich menu and how you unlink it, the target users and the timing of when the changes take effect may vary. As a result, the rich menu may unintentionally continue to be displayed even after you perform the operation to stop it.

For example, if you delete a rich menu without unlinking it from the user, it won't disappear immediately from the user's chat screen. The deleted rich menu will continue to be displayed until the user re-enters the chat screen.

The newly added page clarifies these specifications and considerations for stopping the display of a rich menu, and explains the procedures to prevent unintended rich menus from continuing to be displayed to users.

### Main contents

The main contents of the newly added page are as follows. Since the appropriate procedure for stopping the display varies depending on how the rich menu is applied, this document explains each case.

- [Stop displaying a default rich menu](/docs/messaging-api/stop-displaying-rich-menu/#stop-displaying-default-rich-menu)
- [Stop displaying a per-user rich menu](/docs/messaging-api/stop-displaying-rich-menu/#stop-displaying-per-user-rich-menu)
- [If you are using tab switching (rich menu aliases)](/docs/messaging-api/stop-displaying-rich-menu/#if-you-are-using-tab-switching)
- [Delete unneeded rich menus](/docs/messaging-api/stop-displaying-rich-menu/#delete-unneeded-rich-menu)

If you're a developer who switches rich menus for campaign operations or other purposes, read this page to review your operational workflows.
